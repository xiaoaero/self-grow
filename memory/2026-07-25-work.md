# 2026-07-25 工作记录

## 今日完成

### 1. 动态播报工作0分钟修复

**问题：** 行动中心动态播报中，工作维度的记录（日常、工作日加班、休息日加班）因为没有备注且 `duration=0`，显示为"工作 0分钟"。

**修复：** 后端 `get_activity_feed()` 增加固定时长子类型的友好标签映射：
- `work-daily` → "日常工作"
- `work-overtime-weekday` → "工作日加班"
- `work-overtime-weekend` → "休息日加班"
- 同时覆盖 `relation-offline`、`create-publish`、`finance-review`

**涉及文件：** `backend/db/actions.py`

### 2. 表达训练：再次回答显示"第0次回答"

**问题：** 从历史详情点击"再次回答"后，答题界面显示"第0次回答"，因为 `confirmRetryQuestion()` 中硬编码了 `STATE.currentAttempt = 0`。

**修复：** 改为 `STATE.currentAttempt = (STATE.detailAnswers?.length || 0) + 1`，根据已有回答数计算下次尝试次数。

**涉及文件：** `frontend/js/pages/agent.js`

### 3. 表达训练：返回后最近回答记录不显示新回答

**问题：** 完成回答后点击"返回"，训练首页的"最近回答记录"仍为旧数据，因为 `STATE.history` 只在页面初始化时加载一次。

**修复：** `handleBackToTrain()` 中先调用 `loadHistory()` 重新拉取最新数据，再渲染训练视图。

**涉及文件：** `frontend/js/pages/agent.js`

### 4. 表达训练：详情页未评分回答显示AI分析按钮

**功能：** 历史详情页中，对 `score_total` 为 null 的回答显示"AI 分析"按钮，点击后调用评估 API，完成后自动刷新显示评分结果。支持切换不同回答记录时自动判断。

**涉及文件：** `frontend/js/pages/agent.js`、`frontend/css/pages.css`

### 5. 表达训练：题型选择区添加自定义题目输入框

**功能：** 四个分类按钮下方增加自定义题目输入框，用户可手动输入题目。前端提交到后端后，后端直接保存到数据库（`question_type='custom'`，`source='custom'`），不走 AI 出题流程。自定义题目显示为紫色标签。

**涉及文件：** `frontend/js/pages/agent.js`、`frontend/css/pages.css`、`backend/routers/expression.py`

### 6. 侧边栏经验同步（所有获得经验的地方）

**问题：** 提交行动、完成任务、达成目标时更新了 `AppData.user.exp` 数据，但左下角侧边栏经验条不会实时刷新，需要手动刷新页面。

**修复：** 在所有获得经验的地方补充 `renderSidebarFooter()` 调用：
- 行动板块（手动提交 + AI提交）— 已修复
- 目标板块（`claimGoalReward` + `localClaimGoal`）— 新增
- 任务板块（`claimTaskExp` + `localClaimTaskExp`）— 新增

**涉及文件：** `frontend/js/pages/action.js`、`frontend/js/pages/goals.js`、`frontend/js/pages/tasks.js`

### 7. 本周任务不应显示今日任务

**问题：** 本周任务加载时调用的是 `fetchTodayTasks()`（`/api/tasks`），后端 `get_today_tasks()` 按 `date(created_at) >= today` 过滤，导致今天创建的任务同时出现在今日任务和本周任务中。

**修复：** 
- 后端新增 `get_week_tasks()` 按本周一~周日范围过滤
- 后端新增 `GET /api/tasks/week` 接口
- 前端新增 `fetchWeekTasks()` 调用 `/api/tasks/week`
- `loadWeekTasksFromBackend()` 改为调用 `fetchWeekTasks()`

**涉及文件：** `backend/db/tasks.py`、`backend/routers/tasks.py`、`frontend/js/utils.js`、`frontend/js/pages/tasks.js`

### 8. 任务板块 3 个 Bug 修复（7月25日后续）

**Bug 8a：今日/本周任务数据污染**
- **问题：** `tasks` 全局变量被今日和本周共享，切换标签页时一个的数据覆盖另一个
- **修复：** 拆分为独立变量 `todayTasks` 和 `weekTasks`，各自通过 `todayTasksLoaded` / `weekTasksLoaded` 独立标记加载状态
- **涉及文件：** `frontend/js/pages/tasks.js`

**Bug 8b：看板操作（开始/完成/拖拽）不同步到后端**
- **问题：** `startTask()`、`completeTask()`、`dropTask()` 只做前端状态变更，不调用后端 API，刷新后状态丢失
- **修复：** 三个函数补充 `patchTaskStatusOnBackend()` 调用，同步状态到后端
- **涉及文件：** `frontend/js/pages/tasks.js`

**Bug 8c：`completed_at` 不同步到后端**
- **问题：** `moveTaskToDone()` 设置 `task.completedAt` 但 PATCH 接口只传 `status`，不传 `completed_at`
- **修复：** 
  - `PatchTaskStatusRequest` 增加 `completed_at` 可选字段（`backend/schemas/api.py`）
  - 后端路由接收并传参给 `update_task()`（`backend/routers/tasks.py`）
  - 前端 `patchTaskStatusOnBackend()` 增加 `completedAt` 参数（`frontend/js/utils.js`）
  - `moveTaskToDone()`、`completeTask()` 传 `completedAt` 到后端
- **涉及文件：** `backend/schemas/api.py`、`backend/routers/tasks.py`、`frontend/js/utils.js`、`frontend/js/pages/tasks.js`
