# 2026-07-26 工作记录

## 任务板块重构：本日任务与本周任务完全分离

### 问题现象
在"晓"用户下新建本日任务后，重新进入系统发现该任务也在"本周任务"中显示。原因是 `get_today_tasks` 和 `get_week_tasks` 都基于 `created_at` 日期范围查询（本日任务查 >= today，本周任务查周一至周日），同一天创建的任务天然同时满足两个条件。

### 设计方案
利用 `tasks` 表已有的 `source_type` 字段进行分离：

- `today` — 用户在本日任务页面手动创建的
- `daily` — 定时模板（每日 03:00）自动生成的
- `weekly` — 用户在本周任务页面手动创建的，或每周模板（周一 03:05）生成的

**查询逻辑**：
- `get_today_tasks` → `WHERE source_type IN ('today','daily') AND date(created_at) = today`
- `get_week_tasks` → `WHERE source_type = 'weekly' AND date(created_at) BETWEEN mon AND sun`

预计：两个视图完全正交，互不重叠。

### 引入 task_history 表
新建 `task_history` 表，替代原来在 `tasks` 表中原地标记 `status='expired'` 的方式：

- **每日 03:00**：将昨天 `today`/`daily` 的任务复制到 `task_history`，从 `tasks` 删除
- **每周一 03:05**：将上周 `weekly` 的任务复制到 `task_history`，从 `tasks` 删除
- **历史记录**：按 `archived_at DESC` 排序，支持 status/source_type 筛选
- 已完成的任务保留 `completed` 状态，未完成的标记为 `expired`

### 测试结果
- 创建 `source_type='today'` 任务 → 只出现在本日任务 ✓
- 创建 `source_type='weekly'` 任务 → 只出现在本周任务 ✓
- 历史 API 正常返回空列表 ✓

### 与前版本兼容
- `DELETE FROM tasks` 清空了旧数据，不再存在任务串混问题
- 历史通过 `task_history` 表重新累积，等待每日/每周归档自动填充
