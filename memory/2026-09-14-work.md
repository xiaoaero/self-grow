## 二、排障：`pixi run start` 后点网址打不开

用户贴启动日志后反馈"点击网址进去显示无法访问此页"。用 `curl` 实测定位到**三个原因叠加**：

| # | 原因 | 说明 |
|---|---|---|
| 1 | **`0.0.0.0` 是监听地址不是访问地址** | 浏览器必须用 `http://localhost:3001` / `http://127.0.0.1:3001` |
| 2 | **`GET /` 返回 404** | 根路径从未定义路由；且 `SELF_GROW_FRONTEND_DIR` 未设置 → 后端不 serve 前端 |
| 3 | **`SELF_GROW_JWT_SECRET` 未配置** | 密钥是懒加载的，所以服务**能正常启动**，但一登录就 500 —— 最隐蔽的一条 |

### 修复

- `main.py` 新增 `/` 与 `/login.html` 路由
  - `login.html` 在**项目根**、不在 `frontend/` 下，之前即使配了 `FRONTEND_DIR` 也访问不到
  - `/` 找不到页面时返回带提示的 JSON，不再是裸 404
- `main.py` 的 `lifespan` 启动时调 `auth_service.ensure_jwt_secret()` → **缺密钥直接拒绝启动**（避免"能启动、一登录才 500"的高排查成本）
- 启动日志改为打印真正可用的地址：
  ```
  🌐 登录页：   http://localhost:3001/login.html
  📖 API 文档： http://localhost:3001/docs
  ```
  开启 `TRUSTED_MODE` 时额外打印醒目告警
- `backend/.env` 补上自动生成的 `SELF_GROW_JWT_SECRET`（64 位十六进制）+ `SELF_GROW_FRONTEND_DIR`

验证：`/`、`/login.html`、`/frontend/index.html`、`/favicon.ico`、`/api/health` 全部 200。

## 三、排障：前端走 `npx http-server -p 3000` 时登录页报"无法连接到后端"

### 根因

上一轮把 CORS 从 `*` 收紧成**显式端口列表**（3001 / 5173 / 5500 / 8080 / 8000），**漏了 3000**。
前端在 :3000 发的请求 Origin 不匹配 → 浏览器拦截 → 登录页 catch 到异常 → 显示"后端未启动"（**误导性提示**，实际后端是好的）。

### 修复：别再猜端口，改成规则匹配

- `config.py` 新增 `CORS_ALLOW_ORIGIN_REGEX = r"^https?://(localhost|127\.0\.0\.1)(:\d+)?$"`
- `main.py` 的 `CORSMiddleware` 加 `allow_origin_regex=...`（与显式列表并存），显式列表补 3000
- **只匹配 localhost / 127.0.0.1，不含局域网 IP** —— 公网仍须用 `SELF_GROW_CORS_ORIGINS` 显式指定

实测：

| Origin | 结果 |
|---|---|
| `localhost:3000` | ✅ 200，回显对应 allow-origin |
| `localhost:4321`（任意端口） | ✅ 200 |
| `evil.com` | ❌ 无 allow-origin 头（浏览器拦截） |

### 顺带改进登录页报错

原来只会笼统说"后端未启动"，现在把真实原因摊开：

- 显示**目标地址 `API_BASE`** 与**当前页面 `location.origin`**，一眼看出是不是跨域问题
- `location.protocol === 'file:'` 时给出专门提示（file:// 的 Origin 是 `null`，**故意不放行**：任何本地文件都能调你的 API）
- 补上 `<script src="/api/config.js">`（前端独立服务器时 404 → onerror → 回落默认端口，无副作用）

`docs/安全设计说明.md` 的 CORS 一节补充了正则的由来与 file:// 场景说明。
