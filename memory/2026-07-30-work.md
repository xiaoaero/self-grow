## 3. 睡眠输入修复 + 提交误加 EXP 修复

### 问题1：睡眠时间 input 每次只能输入一个数字
**原因**：两个 time input 的 `onchange` 事件调用了 `updateDynamicForm()` → `renderDynamicForm()` 重建整个表单，重建后另一个输入框的值被重置。
**修复**：改为调用 `updateSleepPreview()`，只更新预览文本，不重建表单。

| 文件 | 改动 |
|------|------|
| `frontend/js/pages/action.js` | 两个 time input 的 onchange 从 `updateDynamicForm()` → `updateSleepPreview()` |
| `frontend/js/pages/action.js` | 新增 `updateSleepPreview()` 函数，轻量更新预览 |
| `frontend/js/pages/action.js` | 睡眠预览从条件渲染改为固定ID元素 |

### 问题2：记录睡眠后再次点击"记录努力"莫名增加 7.5 EXP
**原因**：提交睡眠后清空了 `actionSleepStart/End`，但没有清 `selectedActionCategory` 和 `actionSubType`。再次点击提交时，健康分类下 `!actionSleepStart && !actionSleepEnd` 被代码自动判为"运动模式"，30分钟默认时长按 `(30/60 * 15) = 7.5 EXP` 提交。

**修复**：
- 健康分类不再自动推断子类型，必须显式选择"运动"或"睡眠"
- 提交后清空 `selectedActionCategory` + `actionSubType`
- 新增 `markSleepRecordedToday()` + `isSleepRecordedToday()`，持久化到 localStorage
- `checkSleepRecordedToday()` 异步查询不再重置已记录的标记

| 文件 | 改动 |
|------|------|
| `frontend/js/pages/action.js` | `submitAction()` 健康分类检查改为要求显式子类型 |
| `frontend/js/pages/action.js` | `confirmSubmitAction()` 提交后清空 `actionSubType` + `selectedActionCategory` |
| `frontend/js/pages/action.js` | 新增 `markSleepRecordedToday()` / `isSleepRecordedToday()` 持久化标记 |
| `frontend/js/pages/action.js` | `submitAction()` 拦截改为调用 `isSleepRecordedToday()` |
| `frontend/js/pages/action.js` | `confirmSubmitAction()` 提交睡眠后立即调用 `markSleepRecordedToday()` |
