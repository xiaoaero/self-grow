### 代码勘察得到的现状事实

- `routers/deps.py: get_current_user(user_id: int = Query(...))` —— 只校验 user_id 存在，等同无鉴权
- `routers/users.py:20` 登录 = 按 user_id 取用户，返回 id/name/role，无密码校验
- `db/init.py` 的 users 表**无 password 字段**
- `login.html:34` 原文仍写着"💡 后续版本将支持用户名密码登录"；登录 = 点用户卡片，写入 `localStorage['sg_user']`
- CORS `allow_origins=["*"]`
- **新发现**：`login.html` 写 `sg_user`，但 `frontend/skill-tree/js/utils.js:90` 读 `currentUser` → 编辑器永远拿不到 user_id

### 9 种登录方式适配度评级

| 方案 | 适配度 | 一句话 |
|---|---|---|
| A. URL 参数 user_id（现状） | ★☆☆☆☆ | 等于没有鉴权 |
| B. Session-Cookie | ★★☆☆☆ | 最简单安全，但非浏览器客户端不可用 |
| **C. JWT（Access+Refresh）** | **★★★★★** | **推荐** |
| D. OAuth2 第三方 | ★★☆☆☆ | 依赖外网，局域网部署直接废掉 |
| E. SSO / OIDC | ★☆☆☆☆ | 给 5 人项目上 Keycloak 是过度设计 |
| F. 邮箱 / 短信验证码 | ★★☆☆☆ | 要付费服务，自用反而麻烦 |
| G. Passkey / WebAuthn | ★★☆☆☆ | 技术最好但复杂度高，留作二期 |
| H. API Key | ★★★★☆ | MCP 的唯一现实选择（补充层） |
| I. HTTP Basic | ★★☆☆☆ | 浏览器弹原生框且无法登出 |
| J. 本地免密开关 | ★★★★☆ | 作为开关存在，不是方案 |

### 推荐方案（四层分工）

```
浏览器用户 → 用户名+密码 → JWT（Access 2h + Refresh 30d）
MCP/脚本   → API Key（HTTP 模式）或 环境变量（stdio 本地）
本地开发   → TRUSTED_MODE 开关跳过鉴权
```

选 JWT 而非 Session 的四条理由：MCP 无 Cookie 上下文（不是别扭而是不可用）、
技能树是独立 SPA 且角色要随凭证走、Swagger Authorize 可现场演示、单进程环境无状态更省事。

### 落地设计要点

- 表结构：`users` 加 `password_hash` / `token_version` / `last_login`；新建 `refresh_tokens`、`api_keys`
- 依赖：`passlib[bcrypt]` + `PyJWT`；`pixi.toml` → `pixi update` → `pixi run export-reqs`
- 端点：login / register / refresh / logout / logout-all / password / me
- 401 vs 403：未认证 401，已认证无权限 403
- Token 存放：Access 内存 + localStorage，Refresh 走 httpOnly Cookie
- MCP：stdio 保留 `SELF_GROW_USER_ID`，HTTP 用 `X-API-Key`
- 安全清单 9 项（bcrypt cost≥12、JWT 密钥从 env、失败锁定、Refresh Rotation、CORS 收紧等）
