## 工作内容 1：弹窗点击外部关闭 bug 修复

### 问题
用户反馈：后几个板块（习惯、奖励、目标、任务）右上角的弹窗，设计上不应该通过点击弹窗外部来关闭，但实际点击外部会直接关闭。

### 根因
`frontend/js/app.js:91` 在应用启动时永久绑定了一个监听器：
```javascript
document.getElementById('modal-overlay').addEventListener('click', closeModal);
```
这个监听器直接调用 `closeModal()`，绕过了所有保护机制：
- 绕过了 `closeModalIfNotActive()` 的 `clickOutsideToClose === 'false'` 检查
- 绕过了 `e.target === overlay` 检查（点击弹窗内部也会触发关闭）
- 与 `openModal()` 中按需绑定的带保护监听器冲突

### 修复
`app.js:91` 改为：
```javascript
document.getElementById('modal-overlay').addEventListener('click', function(e) {
    if (e.target === document.getElementById('modal-overlay')) {
        closeModalIfNotActive();
    }
});
```

### 涉及文件
- `frontend/js/app.js` — 修复点击外部关闭逻辑

### 遇到的问题

**electron-builder + winCodeSign 符号链接权限问题**

`app-builder` 的 `rcedit` 步骤需要下载 `winCodeSign-2.6.0.7z` 并用 `7za.exe` 解压。解压时遇到 darwin 平台的符号链接文件，Windows 普通用户没有 `SeCreateSymbolicLinkPrivilege` 权限，7za 报 exit code 2，app-builder 视为致命错误。

- `sign: false` 配置无法绕过（rcedit 也需要 winCodeSign）
- portable 目标同样受影响
- 手动解压 + 占位文件无效（app-builder 每次重新下载解压）

**解决方案**：改用绿色版打包模式
1. `electron-builder --win --dir` 生成 `dist/win-unpacked/`（此步骤成功）
2. `make-portable.js` 自动添加启动脚本、快捷方式脚本、使用说明
3. 用 7za 压缩为 zip

**根本解决**：开启 Windows 开发者模式（设置 → 更新和安全 → 开发者选项），之后即可用 `npm run build` 生成 NSIS 安装包。

## 工作内容 8：打包模式前端路由修复

### 问题
绿色版解压后启动，登录页和主应用渲染异常——CSS/JS 全部 404。

### 根因
后端 `main.py` 将前端静态文件挂载在 `/static` 路径，但 `login.html` 中的 CSS 引用和跳转路径都使用 `frontend/...`（开发模式下的路径约定）。打包模式下浏览器请求 `/frontend/css/variables.css` 返回 404。

同时 `index.html` 中 `config.js` 硬编码为 `http://localhost:3001/api/config.js`，在 Electron 动态端口场景下不可靠。

### 修复

1. **`backend/main.py`**：前端静态文件挂载路径 `/static` → `/frontend`
   - 匹配 `login.html` 中 `frontend/css/...` 引用
   - 匹配 `window.location.href = 'frontend/index.html'` 跳转
   - 匹配 `index.html` 中相对路径 `css/...` → 解析为 `/frontend/css/...`
   - 匹配技能树 iframe `skill-tree/index.html` → 解析为 `/frontend/skill-tree/index.html`

2. **`frontend/index.html`**：`config.js` 改为同源 `/api/config.js` + 跨域 fallback
   - 打包/Electron 模式：同源请求 `/api/config.js`（成功）
   - 开发模式：同源请求失败 → fallback 到 `http://localhost:3001/api/config.js`

## 工作内容 13：今日统计排除睡眠时长

### 问题
行动板块"今日统计"中"今日专注"把睡眠时间也算进去了。记录 8 小时睡眠后，"今日专注"显示 8 小时，但睡觉不是"专注"。

### 根因
`routers/actions.py` 中所有行动的 `duration` 无差别地加到 `focus_minutes`：
```python
focus_minutes = req.duration if req.duration > 0 else 0
```
睡眠记录的 `duration` 是实际睡眠分钟数（如 480），也被算进"今日专注"。

### 修复
`routers/actions.py` 两处修改：
- `create_action`：`sub_type == "health-sleep"` 时 `focus_minutes = 0`
- `ai_submit_actions`：同样排除睡眠时长

### 涉及文件
- `backend/routers/actions.py` — 2处 focus_minutes 条件判断

## 工作内容 15：学习/爱好/魅力维度 EXP 预览显示 0 的 bug 修复

### 问题
选择"学习"维度后，记录努力按钮和预计 EXP 都显示 **0 EXP**，拖拽时长滑块也不变。

### 根因
`getActionButtonPreview()` 最终调用 `rule.calcPreview(subType, duration)` 传两个参数。但学习/爱好/魅力的 `calcPreview` 只声明了一个参数 `function(duration)`：
- `subType`（空字符串 `""`）被当作 `duration` 接收
- 真正的 `duration`（如 30）被当作第二个参数忽略
- `Math.floor("" / 20)` = `Math.floor(0 / 20)` = 0 → 显示 0 EXP

### 修复
统一所有 `calcPreview` 签名为 `function(subType, duration)`，没有子类型的维度忽略第一个参数：
- `study.calcPreview(duration)` → `study.calcPreview(subType, duration)`
- `hobby.calcPreview(duration)` → `hobby.calcPreview(subType, duration)`
- `soul.calcPreview(duration)` → `soul.calcPreview(subType, duration)`
- `renderSubTypeArea` 中调用也统一传两个参数 `rule.calcPreview('', actionDuration)`

### 涉及文件
- `frontend/js/pages/action.js` — 4处 calcPreview 签名统一

## 工作内容 16：拖拽条/数字输入变化时 EXP 预览不实时更新

### 问题
拖拽时长滑块或修改数字输入时，按钮上的"⭐ 记录努力 +X EXP"和子类型区域的"预计: X EXP"不会实时变化，只有切换分类或子类型时才刷新。

### 根因
`sliderChange()` / `numChange()` 只更新了时长数字和结束时间，没有更新 EXP 预览文本。按钮的 EXP 是在 `renderDynamicForm()` 时硬编码到 HTML 里的，拖拽条变化时不会重新渲染整个表单。

### 修复
1. 给预计文本加 ID `exp-preview-text`，给提交按钮加 ID `submit-action-btn`
2. 新增 `updateExpPreview()` 函数，通过 ID 直接更新两处 EXP 文本
3. 在 `sliderChange` 和 `numChange` 末尾调用 `updateExpPreview()`

### 涉及文件
- `frontend/js/pages/action.js` — 新增 `updateExpPreview()`，2处调用，2处 ID 添加
