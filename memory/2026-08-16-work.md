# 2026-08-16 工作记录

## 统一协调 Agent 设计方案 v2 改写

对 `docs/统一协调Agent设计方案.md` 进行了 v2 架构改写。原方案是「单一总 Agent + 一套 8 个工具」；本次根据用户多轮讨论，升级为**多智能体架构**。

### v1 → v2 核心变化

| 维度 | v1（单一 Agent） | v2（主/次 Agent） |
|------|------|------|
| 工具集 | 一个 Agent 拿全部 8 个工具 | 次 Agent 各管各的域，主 Agent 只拿 `route_to` 路由 |
| 结构 | 单 Agent + 泛化 `_call_llm_with_tools` | 主 Agent(Router) + 一组无状态次 Agent 并行 |
| 上下文 | 一次请求塞所有域 | 主 Agent 唯一长上下文；次 Agent 单任务生命周期，任务完即清 |
| 扩展性 | 加域 = 往大工具集塞 | 加次 Agent = 独立新文件 |
| 省 token | 所有工具定义全发 | 只发命中的那一个域 |

### 关键设计决策（用户拍板）

1. **主 Agent = 大脑，次 Agent = 手**：主 Agent 用 `route_to(domain)` 路由，可并行派发多个次 Agent（多意图输入，如"记跑步 + 加任务"）；纯闲聊直接纯文本回复不进次 Agent。

2. **次 Agent 无状态 + 单任务上下文**：任务完成即清上下文。因为关联性由主 Agent 动态编写指令传给次 Agent，次 Agent 没有保留上下文的必要（省 token、防串味）。

3. **反向题全局队列（滑动窗口 = 2）**：所有次 Agent 的反问汇入一条全局 FIFO 队列，前端只渲染队头 2 格；提交一个，队头弹出，下一个顶上。队列与上下文解耦 —— "谁来问"与"问答记忆"分离。

4. **前端独立反问卡片**：每格标注来源 `agent_id`，独立"本轮上下文"；状态流转 `waiting → submitting → replacing`；限流成双避免"反问瀑布"。

5. **跨任务边界判断上移主 Agent**：次 Agent 用机械生命周期计数永远判不对"这是延续还是新一单"（语义问题）；由主 Agent 用对话上下文语义判断，并把相关历史摘要压进次 Agent 定制指令。

### 文档结构变更

- **第 2 章新增「核心架构」**：角色分工表 + 核心循环 + 关键分工原则
- **第 3 章改写**：主 Agent 指令动态生成、反问题队列、route_to 语义路由、并行多意图、写操作确认
- **第 6 章新增「前端交互设计」**：反问题队列 UI + 滑动窗口稳态 + 状态流转
- **第 8 章里程碑**：按新架构重排（M1 先跑通 行动/统计 两域并行反问）
- **第 9 章新增「待定项」**：主 Agent 上下文管理、跨任务延续判定、主 Agent 是否流式 —— 均留到 M5
- **附录 A** 换为 `route_to` 调度工具 Schema；**附录 B** 换为各域次 Agent 工具集
