## Coordinator Agent 反问机制实现

### 完成内容

#### 后端

1. **新建 `ask_user_tool.py`** — 公共反问工具，所有子 agent 共用
   - 返回 `{type: "interrupt", question, options, domain, domain_label}`
   - `DOMAIN_LABELS` 映射 6 个域的 emoji 标签

2. **6 个子 agent 全部接入 `ask_user`**
   - `action_agent.py` / `query_agent.py` / `goal_agent.py` / `task_agent.py` / `habit_agent.py` / `reward_agent.py`
   - 每个 agent 的工具列表新增 `ask_user`
   - `agents/__init__.py` 导出 `ask_user` 和 `DOMAIN_LABELS`

3. **`graph.py` — dispatch_subgraphs 改造**
   - 新增 `_extract_interrupts_from_agent_result()` 检测子 agent 返回的 interrupt
   - 检测到 interrupt 时中断该子 agent，不加入 results
   - 所有 interrupt 收集后统一返回

4. **`routers/coordinator.py` — resume 端点改造**
   - resume 时清空之前的 interrupts/results/pending_tasks
   - 将用户回答作为新的 `user_message` 重新执行主图

5. **`prompts/coordinator.py`** — 所有 6 个子 Agent 提示词补充 `ask_user` 参数说明和 `domain` 参数要求

#### 前端

1. **`chat.js` — FIFO 队列管理**
   - `interruptQueue[]` 存放所有待处理 interrupt
   - `maxVisibleCards: 2` 限制最多同时显示 2 张卡片
   - `_refreshInterruptArea()` — FIFO 渲染，超出显示排队提示
   - `_createInterruptCard()` — 卡片含域名标签 + × 跳过按钮 + 文本输入框 + 选项按钮
   - `skipInterrupt()` — 跳过某张卡片
   - `resumeInterrupt()` — 回答后自动出队下一张

2. **`chat.css` — 卡片样式**
   - `.chat__interrupt-header` / `.chat__interrupt-domain` / `.chat__interrupt-skip`
   - `.chat__interrupt-input-row` / `.chat__interrupt-input` / `.chat__interrupt-send`
   - `.chat__interrupt-queue-hint`

### 数据流

```
用户发消息 → 主图 router → dispatch 并行执行子 agent
  → 某子 agent 调用 ask_user → 返回 interrupt
  → dispatch 收集 interrupts，其他子 agent 继续
  → 返回 { reply, interrupts: [...], results: [...] }
  → 前端渲染 interrupt cards（最多 2 张，其余入队）

用户回答卡片 → /api/coordinator/resume → 后端重新执行主图
  → 返回新 reply + 可能新的 interrupts → 前端更新队列
```

**Why:** 子 agent 在缺少必要信息时需要向用户反问，之前 ask_user 只在提示词中提到但未实现。
**How to apply:** 后续如有新子 agent，需导入 `ask_user` 并加入工具列表，提示词中补充 `domain` 参数要求。
