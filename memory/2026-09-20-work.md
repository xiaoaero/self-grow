## 一、compose 新增 mysql 服务

新增 `mysql` 服务（`mysql:8.0`）：

- **不对外发布端口**（只有 compose 网络内可连）；调试用的 `127.0.0.1:3307` 注释掉
- `command` 带 `--character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
  --default-time-zone=+08:00`（时区与服务端也设，与连接层双保险）
- 环境变量都是 `${VAR:-占位默认值}`，注释里**明确写「生产必须改」**。
  为什么不用 `${VAR:?必填}`：compose 在**解析整个文件**时就插值，
  缺变量会连「只用 SQLite」的人也起不来，**破坏回退路径**
- `healthcheck` 用 **`mysqladmin ping`** 而不是 TCP 探测 —— 初始化期间 MySQL 会起一个
  **临时 server** 监听 3306，TCP 通但 SQL 还不能跑。
  `$$MYSQL_ROOT_PASSWORD`（**双 `$`**）才不会被 compose 在宿主机展开成空串
- 卷 `mysql_data`，注释写明「这是 MySQL 模式的全部业务数据，备份用 `mysqldump --single-transaction`」

`app` / `mcp` 都加：

- `depends_on: mysql: condition: service_healthy` —— 否则后端会在 MySQL 还没 ready 时就
  `init_db()`，直接连不上
- 数据库环境变量。**`SELF_GROW_MYSQL_HOST: mysql`**（compose 服务名）——
  写 `127.0.0.1` 会指向容器自己，报错很难懂，注释里标了
- 池大小：app 20 / mcp 10（MCP 一次调一个工具，并发远低于主站）

**关键补丁**：compose 头部注释加了「**已经在跑 SQLite 版本想切 MySQL，必须先迁数据**，
否则 app 在空库重建 22 张表、看起来像数据全丢了」，并给出三条命令。

## 二、🐛 真 bug：派生表没别名 → MySQL 1248

**发现方式**：端点冒烟时 `/api/expression/stats` 返回 **500**：

```
pymysql.err.OperationalError: (1248, 'Every derived table must have its own alias')
```

根因：`db/expressions.py::get_user_stats()` 里

```sql
SELECT AVG(score_total) FROM (
    SELECT score_total FROM expression_answers WHERE ... LIMIT 5
)                       -- ← 缺 `AS recent`
```

**MySQL 强制派生表带别名，SQLite 不要求** —— 所以本地用 SQLite 开发时一直没暴露。

**为什么测试没拦住**：150 个用例里**没有一个打表达训练 API**。
SQLite 下这条 SQL 完全正常，MySQL 下才炸 —— 典型的「只在另一个后端炸」的问题。

### 顺手全库扫了一遍同类问题

**全库扫出 2 处**：

1. `get_user_stats`（`FROM (SELECT ... LIMIT 5)`）
2. `count_sql` —— **f-string 拼出来的** `f"SELECT COUNT(*) FROM ({base_sql} {having_sql})"`，
   第一版扫描器**漏了它**（因为括号后不是 `SELECT` 而是 `{base_sql}`）

两处都加上别名，复扫 **TOTAL = 0**。第二处靠 grep 字面量根本搜不到，
**只有全库扫描才捞得出来**。

### 固化成两层防护

- **`tests/test_sql_dialect_lint.py`（5 个用例）** —— 静态扫描，两个后端下都跑。
  规则：① 派生表必须有别名 ② 不要用 `INSERT OR REPLACE`（MySQL 的 `REPLACE INTO`
  语义不同，不能机械转）。**每条规则都配一个「灵敏度自检」用例**
- **`tests/test_expression_endpoints.py`（12 个用例）** —— 把表达训练的全部 GET 路径跑一遍

## 三、⚠️ 隐患：MySQL 锁等待默认等一年 → 整站静默挂死

跑 MySQL 全量测试时**反复卡在半路、没有任何报错输出**。定位后是两个默认值叠加：

- MySQL 的 **`lock_wait_timeout` 默认 `31536000` 秒（一年）** —— 只要有一个连接持有
  元数据锁/行锁不放，其它连接就无限期等
- DBUtils 的 **`blocking=True` 池满时同样无限等待**（没有超时）

两者叠加 = 「接口不报错也不返回、整个 worker 挂死」，**且日志里什么都没有** ——
最难排查的那种。

**修法**：`db/backend.py::_INIT_COMMAND` 里与 `time_zone` 拼成一条 `SET`：

```sql
SET time_zone = '+08:00', lock_wait_timeout = 30, innodb_lock_wait_timeout = 30
```

30 秒对正常业务绰绰有余；真等 30 秒说明已经出问题了 ——
这时**快速失败远比"一直装作还在处理"有价值**。

### 试过但**放弃**的方案：TRUNCATE 重置测试库

`db/testing.py` 想用 `TRUNCATE` 替代 `DROP TABLE`（更快 + 顺带归零 `AUTO_INCREMENT`，
而测试里有硬编码依赖自增从 1 开始）→ **实测直接卡死**。
InnoDB 的 TRUNCATE 要拿元数据锁并重建表空间，连接池里其它连接的状态让它一直等。
**失败表现是 pytest 停在半路、没有任何输出。** 已回退到 DROP 版并把教训写进注释。

## 六、踩坑记录

1. **扫描器切片太短 → 静默漏报**：用 `src[m.end():m.end()+12].lstrip()` 判断
   「括号后是不是 SELECT」，但换行 + 16 空格缩进就能吃掉 12 个字符 → 得到空串 →
   判定「不是子查询」→ **真正的 bug 被跳过**。改用正则 `\s*SELECT\b` 并给足窗口。
   ⚠️ **一个"永远返回 0"的检查器比没有检查器更危险** —— 后来给每条规则都加了灵敏度自检用例
2. **别名识别被 `"""` 挡住**：正则 lookahead 写成 `(?=$|[,\s)])`，
   而三引号 SQL 里别名后面紧跟 `"""` → 已修好的代码仍被判违规。改用 `(?![A-Za-z0-9_])`
3. **lint 误报了自己**：`db/dialect.py` 里有一句解释「不要用 `INSERT OR REPLACE`」的**注释**
   被判违规。修法：用 `tokenize` 剥掉 COMMENT token
   （不能用正则按 `#` 切 —— SQL 里可能出现 `#`），且**保留行号**
4. **`tuple(dict)` 给的是键名不是值**：对比脚本里 `tuple(row)` 对 `sqlite3.Row` 是对的，
   对 PyMySQL 的 dict 行会返回 keys → 24 行全「不一致」。要用 `tuple(dict(row).values())`。
   **差点误判成数据迁移有问题**
5. **被 kill 的测试进程会干扰后续运行**：出现「`test_auth` 单独跑 17 passed、
   和其他文件一起跑就 17 failed」的怪现象。原因是**多个 pytest 并发写同一个测试库**。
   判据：**失败结果不可复现**时先怀疑这个
6. **后台任务约 2 分钟被切掉**：`run_in_background` 的 docker build 与 pytest 都遇到过
   「显示 completed 但实际没跑完」。长任务改前台（≤10 分钟）或分批
7. **`xargs` 在本环境报 `environment is too large for exec`** → 直接写循环
