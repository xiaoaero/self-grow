# 2026-08-01 工作记录

## 1. AI 习惯分析性能排查

### 问题
用户反馈点击"AI 习惯分析"后等待数分钟才出结果（约 1000 字符）。

### 排查过程

1. **检查 `ai_client.py`**：`ChatOpenAI` 未设 `request_timeout`，httpx 默认 5 秒超时；openai SDK 默认 `max_retries=2`，超时后静默重试放大延迟。每次调用都 new 一个 `ChatOpenAI` 实例，无连接复用。
2. **检查 `ai_habit_service.py`**：`max_tokens=2048`，生成约 1000 字符绰绰有余。
3. **检查模型**：用户使用 `qwen3.7-max-2026-05-20`，属于**推理模型**（思考链模型），`max_tokens` 计的是**思考部分 + 正文**。

### 优化方案（4 项）

#### A. `ai_client.py` 配置修正
- `request_timeout=300`（显式覆盖 httpx 默认 5s）
- `max_retries=0`（关闭 SDK 默认 2 次重试）
- 模块级 `_get_llm()` 单例缓存，复用 TCP/TLS 连接池
- 新增 `call_ai_text_stream()` 流式生成接口

#### B. 流式端点 `POST /api/habits/ai-insights/stream`
- 后端 SSE StreamingResponse，`X-Accel-Buffering: no` 防 nginx 缓冲
- 服务层错误以 SSE 事件送达前端，不悬挂连接
- 前端 `fetchHabitAIInsightsStream()` 手写 SSE 解析器
- 提交时先走流式，失败自动降级到非流式

#### C. 前端交互优化
- `submitHabitAIAnalysis()` 流式打字机输出，首 token 即现
- 失败降级到原 `fetchHabitAIInsights()` 非流式接口

### 踩坑记录

**推理模型 max_tokens 含思考部分**（关键教训）：

把 `max_tokens` 从 2048 压到 1024 后，流式返回正常但正文被截断（思考链吃掉大部分额度），非流式降级直接 `content: 0 字符`。日志里"流式完成 + 非流式 0 字符"是同一个问题，不是网络错误。

最终恢复 `max_tokens=4096`，给思考部分预留空间。
