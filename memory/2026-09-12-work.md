# 2026-09-12 工作记录

## 技能树 AI（Agent）功能专项复查

用户要求"重点看技能树 agent 功能"。复查范围：`services/skill_tree_ai/*`、`routers/skill_tree_ai.py`、`frontend/skill-tree/js/ai-bridge.js`。

### 🔥 最严重：AI 生成的树全部叠在 (0,0)

`tools.py` 的 `replace_tree` / `create_nodes_batch` / `create_node` 对坐标一律 `n.get("x", 0)`，
而提示词里只是"**尽量**给出合理的 x/y 坐标"。LLM 一旦省略坐标，**所有节点重叠在一个点上**，
用户看到的就是"AI 生成了树但只看得到一个节点"。

新增两个辅助函数：

| 函数 | 作用 |
|---|---|
| `_has_valid_coords(node)` | 判断 LLM 是否给了有效坐标（x、y 全 0 视为未指定） |
| `_auto_layout(nodes, connections, start_x, start_y, gap_x, gap_y)` | BFS 按层级排布：根一列，每层向右 200px，同层垂直 110px |

接入策略：**只有当"所有新节点都没有有效坐标"时才自动布局**；给了坐标则原样保留，不抢用户的排版。
有 `parent_id` 时相对父节点排布（`父x + 200`）。

实测结果：

```
省略坐标 → 根(80,80) 子A(280,80) 子B(280,190) 孙1(480,80)   ✅ 无原点、无重叠
给定坐标 → (500,300) (700,400)                              ✅ 原样保留
挂到父节点 → 父(100,100) 子1(300,100) 子2(300,210)          ✅ 相对父节点
```

### 其余 6 项修复

1. **resume 用旧树快照，会覆盖用户手动改动**
   `ResumeRequest` 新增可选 `tree` 字段；`resume_skill_tree_chat(tree=...)` 把 tree 放进 `ainvoke` 的 input
   （`tree` 是普通字段而非 `operator.add`，放进 input 即整体覆盖），前端 resume 时带上当前树。

2. **纯聊天也刷新画布 + 弹"AI 已更新技能树"**
   `_handleResponse` 原先用 `executed_tools.some(t => t.success)` 判断，而 `send_reply` 也返回 success
   → 纯对话也会整树重绘并弹提示。改为**以 `data.diffs` 非空为准**。

3. **AI 改动不落盘**
   `_applyTree()` 末尾补 `app.sidebar._saveCurrentTree()`（写 localStorage + 后端草稿），
   否则 AI 的修改要等用户手动点"保存"才留得住。

4. **连线样式往返丢失**
   `buildTreePayload()` 原来只发 `id/from/to`，服务端重建连线后 color / dashed / showArrow 全部丢失。补齐三个字段。

5. **确认后参数可能被 AI 改写**（确认删 A、结果删了 B）
   resume 时原本只说"用户已确认操作 X"，LLM 重新调用会自己再生成参数。
   改为把 `pending['args']` 序列化后回灌，并要求"原样使用这些参数 + `confirm=True` 重新调用"。

6. **内存 checkpointer 会话失效无兜底**
   MemorySaver 重启即丢，前端 resume 报 404 时用户一脸茫然。
   前端捕获 404 / 会话相关错误 → `resetSession()` + 提示"后端可能重启，已自动重置"。
