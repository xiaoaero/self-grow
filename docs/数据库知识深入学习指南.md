# 第一部分：数据库基础概念速过

## 1.1 什么是数据库？

数据库（Database）就是一个**有组织地存储和管理数据**的系统。

### 为什么不用文件存数据？

假设你要存储用户信息，用文件的方式：

```python
# 用文件存数据（❌ 不推荐）
# users.txt
# id=1, name=test, level=188
# id=2, name=admin, level=99

# 读取时需要自己解析
with open('users.txt', 'r') as f:
    for line in f:
        parts = line.strip().split(', ')
        user = {k.split('=')[0]: v for k, v in [p.split('=') for p in parts]}
```

问题：
- **查询慢**：要找 ID=5 的用户，必须遍历整个文件
- **并发冲突**：两个人同时写文件，数据会损坏
- **数据冗余**：用户 ID 出现在多个文件中，改一处要改全部
- **没有事务**：写到一半崩溃了，数据不一致

### 用数据库存数据（✅ 推荐）

```sql
-- 用数据库存数据
SELECT * FROM users WHERE id = 5;  -- 毫秒级查询
INSERT INTO users (name, level) VALUES ('test', 188);  -- 自动处理并发
```

数据库的优势：
- **查询高效**：索引让查询从 O(n) 变为 O(log n)
- **并发安全**：锁机制保证多人同时操作不冲突
- **数据一致**：事务保证要么全部成功，要么全部失败
- **结构化**：表结构定义了数据的格式

## 1.2 关系型 vs 非关系型数据库

### 关系型数据库（SQL）

用**表（Table）**存储数据，表之间通过**外键**建立关系。

```
┌──────────────┐         ┌──────────────┐
│   users      │         │   tasks      │
├──────────────┤         ├──────────────┤
│ id (PK)      │←──FK───│ user_id      │
│ name         │         │ title        │
│ level        │         │ status       │
└──────────────┘         └──────────────┘

查询语言：SQL（Structured Query Language）
代表产品：SQLite、MySQL、PostgreSQL
```

### 非关系型数据库（NoSQL）

不依赖表结构，数据以各种格式存储。

```
文档型（MongoDB）：
{
    "_id": 1,
    "name": "test",
    "tasks": [
        {"title": "学习", "status": "todo"},
        {"title": "运动", "status": "done"}
    ]
}

键值型（Redis）：
user:1 → {"name": "test", "level": 188}
```

### 对比

| 特性 | 关系型（SQL） | 非关系型（NoSQL） |
|------|-------------|-----------------|
| 数据结构 | 固定表结构 | 灵活结构 |
| 查询语言 | SQL | 各产品不同 |
| 事务支持 | ✅ 强 | ⚠️ 弱或无 |
| 扩展方式 | 垂直（升级服务器） | 水平（加服务器） |
| 一致性 | 强一致 | 最终一致 |
| 适用场景 | 结构化数据、复杂查询 | 非结构化数据、高并发读写 |

**你的项目用的是 SQLite（关系型）**，因为数据结构明确，需要事务保证。

## 1.4 表、行、列、主键、外键

### 表（Table）

表是数据库中存储数据的基本单位，类似于 Excel 的一个工作表。

```sql
-- 用户表
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- 主键，自动递增
    name TEXT NOT NULL,                     -- 用户名，不能为空
    role TEXT NOT NULL DEFAULT 'user',      -- 角色，默认 'user'
    level INTEGER NOT NULL DEFAULT 1,       -- 等级，默认 1
    exp INTEGER NOT NULL DEFAULT 0,         -- 经验值
    total_exp INTEGER NOT NULL DEFAULT 0,   -- 总经验值
    streak INTEGER NOT NULL DEFAULT 0,      -- 连续天数
    joined TEXT NOT NULL DEFAULT (date('now'))  -- 加入日期
);
```

### 列（Column）

列定义了数据的字段和类型：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY, AUTOINCREMENT | 主键，自动递增 |
| `name` | TEXT | NOT NULL | 用户名，不能为空 |
| `role` | TEXT | NOT NULL, DEFAULT 'user' | 角色，有默认值 |
| `level` | INTEGER | NOT NULL, DEFAULT 1 | 等级 |
| `joined` | TEXT | DEFAULT (date('now')) | 加入日期，默认当前日期 |

### 行（Row）

行是表中的一条记录：

```
id=1, name='test', role='user', level=188, exp=136388, total_exp=6682, streak=21, joined='2026-01-15'
id=2, name='admin', role='admin', level=99, exp=45000, total_exp=45000, streak=7, joined='2026-06-01'
```

### 主键（Primary Key）

主键是每行数据的**唯一标识**：

```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
-- PRIMARY KEY：唯一且不能为空
-- AUTOINCREMENT：自动递增（1, 2, 3, ...）
```

```sql
-- 复合主键（两个字段组合唯一）
PRIMARY KEY (user_id, dimension_key)
-- 一个用户在一个维度只能有一条记录
```

### 外键（Foreign Key）

外键建立表之间的**关联关系**：

```sql
-- tasks 表
user_id INTEGER NOT NULL,
FOREIGN KEY (user_id) REFERENCES users(id)
-- user_id 必须是 users 表中已存在的 id
```

```
users 表                    tasks 表
┌────┬────────┐            ┌────┬─────────┬─────────┐
│ id │ name   │            │ id │ user_id │ title   │
├────┼────────┤            ├────┼─────────┼─────────┤
│  1 │ test   │←───────────│  1 │    1    │ 学习网络 │
│  2 │ admin  │←───────────│  2 │    1    │ 运动30分 │
└────┴────────┘            │  3 │    2    │ 写代码   │
                           └────┴─────────┴─────────┘
                           user_id=1 的两条任务属于 test 用户
                           user_id=2 的一条任务属于 admin 用户
```

# 第二部分：Python 常用数据库选型

## 2.1 SQLite

### 什么是 SQLite？

SQLite 是一个**嵌入式关系型数据库**，整个数据库存储在一个文件中，不需要单独的服务器进程。

```python
# SQLite 的使用极其简单
import sqlite3

# 连接数据库（文件不存在会自动创建）
conn = sqlite3.connect('data.db')

# 执行 SQL
conn.execute('CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)')
conn.execute('INSERT INTO users (name) VALUES (?)', ('test',))
conn.commit()

# 查询
rows = conn.execute('SELECT * FROM users').fetchall()
```

### SQLite 的特点

| 特性 | 说明 |
|------|------|
| 部署 | 零配置，一个文件就是整个数据库 |
| 并发 | 单写多读（WAL 模式下可以读写并发） |
| 存储 | 整个数据库就是一个 `.db` 文件 |
| 性能 | 单机场景下非常快 |
| 限制 | 不支持网络访问，不适合高并发写入 |

### 你的项目为什么选 SQLite？

```python
# backend/config.py
DB_PATH = os.path.join(DATA_DIR, "data.db")
```

原因：
1. **单用户/少用户**：个人成长系统，通常只有自己用
2. **零部署**：不需要安装 MySQL/PostgreSQL 服务
3. **便携性**：整个数据库就是一个文件，备份/迁移方便
4. **部署友好**：Docker 部署时不需要额外的数据库服务

## 2.2 MySQL

### 什么是 MySQL？

MySQL 是最流行的**开源关系型数据库**，广泛用于互联网应用。

```python
# MySQL 需要安装服务，通过网络连接
import pymysql

conn = pymysql.connect(
    host='localhost',
    port=3306,
    user='root',
    password='password',
    database='self_grow'
)
```

### MySQL vs SQLite

| 特性 | MySQL | SQLite |
|------|-------|--------|
| 架构 | C/S（客户端-服务器） | 嵌入式（文件） |
| 并发 | 支持高并发读写 | 单写多读 |
| 部署 | 需要安装服务 | 零配置 |
| 网络 | 支持远程连接 | 仅本地文件 |
| 适用 | 大型网站、多用户 | 单机应用、嵌入式 |

### 什么时候该用 MySQL？

- 用户量 > 100
- 需要多人同时写入
- 需要远程访问数据库
- 需要主从复制/读写分离

### MongoDB vs 关系型数据库

### 什么时候用 MongoDB？

- 数据结构经常变化
- 需要存储嵌套/复杂结构
- 需要高并发读取
- 日志、事件、用户行为数据

## 2.5 Redis

### 什么是 Redis？

Redis 是**内存键值数据库**，速度极快（10万+ QPS），常用于缓存。

# 第三部分：ORM vs 原生 SQL

## 3.1 什么是 ORM？

ORM（Object-Relational Mapping，对象关系映射）让你**用 Python 对象操作数据库**，而不需要写 SQL。

### 不用 ORM（原生 SQL）

```python
# 你的项目现在的写法
conn = get_conn()
row = conn.execute(
    "SELECT * FROM tasks WHERE user_id = ? AND status = ?",
    (user_id, 'todo')
).fetchall()
conn.close()
return [dict(r) for r in rows]
```

### 用 ORM（SQLAlchemy）

```python
# 如果用 SQLAlchemy ORM
class Task(Base):
    __tablename__ = 'tasks'
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey('users.id'))
    title = Column(String)
    status = Column(String)

# 查询
tasks = session.query(Task).filter_by(user_id=user_id, status='todo').all()
# 不需要写 SQL，Python 代码直接操作
```

### 用 ORM（Peewee）

```python
# 如果用 Peewee ORM
class Task(Model):
    user_id = IntegerField()
    title = CharField()
    status = CharField()

    class Meta:
        database = db

# 查询
tasks = Task.select().where(Task.user_id == user_id, Task.status == 'todo')
```

---

## 3.2 ORM 的优势

### 1. 代码简洁

```python
# 原生 SQL：需要手动拼接
where_clauses = ["user_id = ?"]
where_params = [user_id]
if status and status != "all":
    where_clauses.append("status = ?")
    where_params.append(status)
if category and category != "all":
    where_clauses.append("category = ?")
    where_params.append(category)
where_sql = " AND ".join(where_clauses)
rows = conn.execute(f"SELECT * FROM tasks WHERE {where_sql}", where_params).fetchall()

# ORM（SQLAlchemy）：链式调用
query = session.query(Task).filter(Task.user_id == user_id)
if status and status != "all":
    query = query.filter(Task.status == status)
if category and category != "all":
    query = query.filter(Task.category == category)
tasks = query.all()
```

### 2. 类型安全

```python
# 原生 SQL：字符串拼接，容易出错
conn.execute(f"UPDATE tasks SET status = '{new_status}' WHERE id = {task_id}")
# 如果 new_status 包含单引号，会 SQL 注入！

# ORM：自动参数化
task.status = new_status
session.commit()
# ORM 自动处理转义，不会注入
```

## 3.4 你的项目为什么用原生 SQL？

简单、清晰、没有 ORM 的魔法。

## 4.4 事务与连接管理

### 什么是事务？

事务是一组操作，要么**全部成功**，要么**全部失败**。

```python
# 事务示例：领取任务奖励
conn = get_conn()
try:
    # 1. 检查任务是否已领取
    row = conn.execute("SELECT claimed FROM tasks WHERE id = ?", (task_id,)).fetchone()
    if row["claimed"]:
        return None  # 已领取，不操作

    # 2. 标记为已领取
    conn.execute("UPDATE tasks SET claimed = 1 WHERE id = ?", (task_id,))

    # 3. 增加用户经验
    conn.execute("UPDATE users SET exp = exp + ? WHERE id = ?", (exp_amount, user_id))

    # 4. 全部成功，提交
    conn.commit()
    return {"exp_earned": exp_amount}
except Exception as e:
    # 出错，回滚（撤销所有操作）
    conn.rollback()
    raise
finally:
    conn.close()
```

### 你的项目中的事务模式

```python
# 简单模式（大多数函数）
def create_task(user_id, title, category, ...):
    conn = get_conn()
    cursor = conn.execute(
        "INSERT INTO tasks (...) VALUES (...)",
        (...)
    )
    new_id = cursor.lastrowid
    conn.commit()  # 提交事务
    conn.close()
    return new_id
```

**注意**：你的项目中大部分函数没有显式事务管理，依赖 SQLite 的自动提交。对于单条操作这是可以的，但批量操作应该用事务。

# 第五部分：数据库优化

## 5.1 索引原理

### 什么是索引？

索引就像书的**目录**，让查询不需要扫描整张表。

```
没有索引：
  查找 user_id=5 的任务
  → 扫描 tasks 表的每一行
  → 100 万行数据 = 100 万次比较
  → 耗时：500ms

有索引：
  查找 user_id=5 的任务
  → 查索引树（B-Tree）
  → 直接定位到 user_id=5 的行
  → 耗时：1ms
```

### B-Tree 索引

SQLite 默认使用 B-Tree 索引：

```
B-Tree 结构（以 user_id 索引为例）：

                    ┌─────────┐
                    │  50     │
                    └────┬────┘
                 ┌───────┴───────┐
                 ▼               ▼
           ┌─────────┐     ┌─────────┐
           │  25     │     │  75     │
           └────┬────┘     └────┬────┘
           ┌────┴────┐     ┌────┴────┐
           ▼         ▼     ▼         ▼
      ┌──────┐  ┌──────┐ ┌──────┐ ┌──────┐
      │10,15 │  │30,40 │ │60,70 │ │80,90 │
      └──────┘  └──────┘ └──────┘ └──────┘

查找 user_id=60：
1. 从根节点开始：60 > 50，走右边
2. 60 < 75，走左边
3. 找到 60，直接定位到对应行
```

### 复合索引

复合索引是多个字段的组合索引：

```sql
-- 你的项目中的复合索引
CREATE INDEX idx_action_logs_user_date ON action_logs(user_id, start_time);
CREATE INDEX idx_tasks_user_source ON tasks(user_id, source_type, created_at);
```

**复合索引的最左匹配原则**：

```
索引 (user_id, source_type, created_at)

✅ 能用到索引的查询：
WHERE user_id = 1
WHERE user_id = 1 AND source_type = 'today'
WHERE user_id = 1 AND source_type = 'today' AND created_at > '2026-01-01'

❌ 用不到索引的查询：
WHERE source_type = 'today'  （跳过了 user_id）
WHERE created_at > '2026-01-01'  （跳过了 user_id 和 source_type）
```

## 5.4 写入优化

### WAL 模式（Write-Ahead Logging）

```python
# 你的项目已启用 WAL
conn.execute("PRAGMA journal_mode=WAL")
```

**WAL vs 传统日志模式**：

```
传统模式（DELETE）：
  写入时锁定整个数据库 → 其他读写都等待
  性能差，并发低

WAL 模式：
  写入写入 WAL 文件 → 读取不受影响
  读写可以并发，写入性能提升 2-3 倍
```

```
WAL 模式的工作原理：

客户端 A（写入）          客户端 B（读取）
     │                        │
     │  写入 WAL 文件          │  读取原始数据库
     │  ──────────────→       │  ←──────────────
     │                        │
     │  WAL checkpoint        │  （读取不受影响）
     │  合并到主数据库         │
```

### 批量写入

```python
# ❌ 不好：逐条插入（每次都要写磁盘）
for task in tasks:
    conn.execute("INSERT INTO tasks (...) VALUES (...)", (...))
    conn.commit()  # 每条都提交，很慢

# ✅ 好：批量插入（一次写磁盘）
conn.execute("BEGIN")
for task in tasks:
    conn.execute("INSERT INTO tasks (...) VALUES (...)", (...))
conn.commit()  # 一次性提交，快很多
```

### busy_timeout

```python
# 你的项目已配置
conn.execute("PRAGMA busy_timeout=5000")
```

**busy_timeout 的作用**：

```
没有 busy_timeout：
  写入冲突 → 立即报错 "database is locked"

有 busy_timeout=5000：
  写入冲突 → 等待 5 秒 → 还是冲突才报错
  给其他客户端留出时间完成写入
```

## 5.5 连接管理

### 你的项目的连接模式


### 为什么你的项目用短连接？

SQLite 是文件数据库，连接开销很小。而且你的项目并发不高，短连接足够。

## 5.6 PRAGMA 优化总结

```python
# 你的项目中的 PRAGMA 配置
conn.execute("PRAGMA journal_mode=WAL")      # WAL 模式：读写并发
conn.execute("PRAGMA busy_timeout=5000")      # 忙等待 5 秒
conn.execute("PRAGMA synchronous=NORMAL")     # 同步级别：正常
```

| PRAGMA | 值 | 作用 | 性能影响 |
|--------|-----|------|---------|
| `journal_mode` | WAL | 读写并发 | 写入提升 2-3 倍 |
| `busy_timeout` | 5000 | 等待锁 5 秒 | 减少 "database is locked" |
| `synchronous` | NORMAL | 同步写入 | 性能提升约 2 倍 |
| `cache_size` | -64000 | 缓存 64MB | 大数据集查询更快 |
| `temp_store` | MEMORY | 临时表在内存 | 复杂查询更快 |

# 第六部分：高并发场景与 SQLite 的局限

## 6.1 SQLite 的并发模型

### 单写多读

SQLite 的核心限制：**同一时刻只能有一个写入者**。

```
客户端 A（写入）          客户端 B（写入）          客户端 C（读取）
     │                        │                        │
     │  写入 lock             │  写入 lock             │  读取
     │  ──────────────→       │  ──────────────→       │  ←──────────────
     │  ✅ 成功               │  ❌ 等待...             │  ✅ 成功
     │                        │                        │
     │  写入完成，释放锁       │  获得锁，写入           │  （读取不受影响）
     │                        │  ✅ 成功               │
```

### WAL 模式下的并发

```
WAL 模式：读写不阻塞

客户端 A（写入）          客户端 B（读取）          客户端 C（读取）
     │                        │                        │
     │  写入 WAL 文件          │  读取（不阻塞）        │  读取（不阻塞）
     │  ──────────────→       │  ←──────────────       │  ←──────────────
     │  ✅ 成功               │  ✅ 成功               │  ✅ 成功
     │                        │                        │
     │  checkpoint            │                        │
     │  合并到主数据库         │                        │
```

### 写写冲突

```
客户端 A（写入）          客户端 B（写入）
     │                        │
     │  开始写入               │  开始写入
     │  ──────────────→       │  ──────────────→
     │  ✅ 获得锁             │  ❌ 等待（busy_timeout=5000）
     │                        │  ...
     │  写入完成               │  ✅ 获得锁
     │                        │  ✅ 写入成功
```

**为什么用单线程？**

```

ThreadPoolExecutor(4)：
  4 个定时任务可能同时写入
  → 触发 "database is locked" 错误
```

### busy_timeout 兜底

```python

```

即使有短暂的写入冲突，也会等待 5 秒而不是立即报错。

## 6.3 什么时候该换数据库？

### SQLite 的瓶颈

| 场景 | SQLite 表现 | 说明 |
|------|-----------|------|
| 并发读取 | ✅ 好 | WAL 模式下读写不阻塞 |
| 并发写入（< 10/s） | ✅ 好 | busy_timeout 能应对 |
| 并发写入（> 100/s） | ❌ 差 | 频繁锁冲突 |
| 多服务器部署 | ❌ 不支持 | SQLite 是单文件，不支持网络 |
| 数据量 > 1GB | ⚠️ 一般 | 性能下降 |
| 需要全文搜索 | ❌ 不支持 | 需要外部引擎 |

### 迁移路径

```
SQLite → MySQL/PostgreSQL

需要迁移的信号：
1. 用户量 > 100
2. 并发写入 > 10/s
3. 需要多服务器部署
4. 数据量 > 1GB
5. 需要高级特性（全文搜索、JSON 索引等）
```

### 迁移示例


# 第七部分：数据库架构设计模式

## 7.1 表设计原则

### 范式化（Normalization）

范式化是将数据拆分到多个表，减少冗余。

```
❌ 反范式化（冗余）：
tasks 表：
  id=1, user_name='test', user_level=188, title='学习'
  id=2, user_name='test', user_level=188, title='运动'
  // user_name 和 user_level 重复存储

✅ 范式化（拆分）：
users 表：id=1, name='test', level=188
tasks 表：id=1, user_id=1, title='学习'
          id=2, user_id=1, title='运动'
// 通过 user_id 关联，不重复存储用户信息
```

### 反范式化（Denormalization）

有时候为了查询性能，故意保留冗余数据。


### 归档实现

```python
# backend/db/batch.py
def archive_daily_tasks(user_id: int):
    """每日 03:00 执行：归档昨天的任务"""
    yesterday = (datetime.date.today() - datetime.timedelta(days=1)).isoformat()

    conn = get_conn()

    # 1. 将未完成的任务标记为 expired
    conn.execute(
        """UPDATE tasks SET status = 'expired'
           WHERE user_id = ? AND source_type IN ('today', 'daily')
           AND date(created_at) = ?
           AND status IN ('todo', 'doing')""",
        (user_id, yesterday),
    )

    # 2. 归档到 task_history
    count = archive_tasks_to_history(conn, user_id, ['today', 'daily'], yesterday, yesterday)

    # 3. 提交
    conn.commit()
    conn.close()
    return count
```

### 归档的好处

| 方面 | 归档前 | 归档后 |
|------|--------|--------|
| tasks 表行数 | 无限增长 | 只保留近期任务 |
| 查询速度 | 越来越慢 | 保持稳定 |
| task_history | 空 | 完整历史记录 |

### 迁移脚本的最佳实践

```python
# 1. 版本号管理
MIGRATION_VERSION = 3

def migrate(conn):
    """执行数据迁移"""
    current_version = get_version(conn)

    if current_version < 1:
        # 迁移 1：添加 sub_type 列
        try:
            conn.execute("ALTER TABLE action_logs ADD COLUMN sub_type TEXT DEFAULT ''")
        except Exception:
            pass
        set_version(conn, 1)

    if current_version < 2:
        # 迁移 2：添加索引
        conn.execute("CREATE INDEX IF NOT EXISTS idx_tasks_user_source ON tasks(user_id, source_type, created_at)")
        set_version(conn, 2)

    if current_version < 3:
        # 迁移 3：数据类型变更
        try:
            conn.execute("ALTER TABLE user_dimensions ADD COLUMN xp_real REAL NOT NULL DEFAULT 0")
            conn.execute("UPDATE user_dimensions SET xp_real = xp")
            conn.execute("ALTER TABLE user_dimensions DROP COLUMN xp")
            conn.execute("ALTER TABLE user_dimensions RENAME COLUMN xp_real TO xp")
        except Exception:
            pass
        set_version(conn, 3)
```

你的项目中，经验值的计算涉及多个表的协作：
