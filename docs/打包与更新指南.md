# 📦 桌面应用打包与更新指南

## 架构概览

```
SelfGrow.exe (Electron 主进程)
  ├── 启动 self-grow-backend.exe (PyInstaller 打包的 FastAPI)
  ├── 等待后端就绪 (轮询 /api/health)
  ├── 创建 BrowserWindow 加载前端页面
  └── 关闭窗口 → 终止后端进程

数据目录: %APPDATA%/SelfGrow/
  ├── data.db        (SQLite 数据库)
  ├── uploads/       (上传文件)
  └── .env           (AI 配置，首次运行自动创建模板)
```

## 产出物

| 产物 | 路径 | 大小 |
|------|------|------|
| 后端 exe | `backend/dist/self-grow-backend/` | ~56 MB |
| 绿色版目录 | `desktop/dist/SelfGrow/` | ~325 MB |
| 绿色版 zip | `desktop/dist/SelfGrow-v{版本}-portable.zip` | ~136 MB |

## 一键构建

```bash
build.bat
```

自动执行：PyInstaller 打包后端 → npm install → electron-builder --dir → make-portable.js 生成 zip。

## 分步构建

### Step 1: 打包后端

```bash
cd backend
pixi run pyinstaller --clean --noconfirm self_grow_server.spec
```

- 输出：`backend/dist/self-grow-backend/`（onedir 模式）
- 耗时：2-5 分钟
- `--clean` 清除缓存，`--noconfirm` 覆盖已有输出

### Step 2: 安装 Electron 依赖（首次或 package.json 变更时）

```bash
cd desktop
npm install
```

### Step 3: 打包 Electron 应用

```bash
cd desktop
npm run build:dir      # 生成 dist/win-unpacked/
node make-portable.js  # 重命名 + 添加脚本 + 打 zip
```

### Step 4: 测试

解压 zip → 双击 `Self Grow.exe` → 验证功能正常。

### Step 5: 发布

```bash
git tag v1.x.0
git push origin v1.x.0
# 上传 zip 到 Gitee Release 或其他分发渠道
```

## 更新流程（按改动范围）

### 只改了前端

无需重新打包后端，直接替换前端文件：

```bash
rm -rf desktop/dist/SelfGrow/resources/frontend
cp -r frontend desktop/dist/SelfGrow/resources/frontend
cp login.html desktop/dist/SelfGrow/resources/login.html
cd desktop/dist && node ../make-portable.js
```

### 只改了后端

无需重新打包 Electron，只需重新打包后端 exe：

```bash
cd backend && pixi run pyinstaller --clean --noconfirm self_grow_server.spec
rm -rf desktop/dist/SelfGrow/resources/backend
cp -r backend/dist/self-grow-backend desktop/dist/SelfGrow/resources/backend
cd desktop/dist && node ../make-portable.js
```

### 前后端都改了

```bash
build.bat
```

### 改了版本号

1. 修改 `desktop/package.json` 中的 `version` 字段
2. 执行 `build.bat`（make-portable.js 会自动使用新版本号命名 zip）

## 打包模式关键设计

### 路由映射

| 请求路径 | 后端处理 | 说明 |
|----------|---------|------|
| `/` | `login.html` | 登录页 |
| `/frontend/*` | 前端静态文件 | CSS/JS/图片/技能树 |
| `/api/*` | FastAPI 路由 | 后端 API |
| `/uploads/*` | 静态文件 | 上传的图片 |
| `/api/config.js` | 动态生成 JS | 注入 `window.__SELF_GROW_API_BASE__` |

### 数据目录分离

| 模式 | 数据目录 | 说明 |
|------|---------|------|
| 开发模式 | `backend/` | data.db、uploads、.env 都在源码目录 |
| 打包模式 | `%APPDATA%/SelfGrow/` | 用户数据独立于安装目录，更新不丢失 |

通过 `SELF_GROW_PACKAGED` 环境变量切换，`config.py` 的 `get_data_dir()` 自动判断。

### API 地址注入

前端通过 `/api/config.js` 端点动态获取后端地址：

```javascript
// 打包/Electron 模式：同源请求
<script src="/api/config.js"></script>

// 开发模式：跨域 fallback
<script src="/api/config.js" onerror="">
<script>
if (!window.__SELF_GROW_API_BASE__) {
    var s = document.createElement('script');
    s.src = 'http://localhost:3001/api/config.js';
    s.onerror = function() {};
    document.head.appendChild(s);
}
</script>
```

## 常见问题

### PyInstaller 报 "Device or resource busy"

旧的后端 exe 进程还在运行，先关闭：

```bash
taskkill /F /IM self-grow-backend.exe
taskkill /F /IM "Self Grow.exe"
```

### electron-builder 报 winCodeSign 符号链接错误

Windows 普通用户没有创建符号链接权限。解决方案：

1. **开启 Windows 开发者模式**：设置 → 更新和安全 → 开发者选项 → 开启
2. 开启后运行 `cd desktop && npm run build` 即可生成 NSIS 安装包
3. 不开启则使用绿色版 zip（`build.bat` 默认流程）

### Windows Defender 误报

PyInstaller 打包的 exe 常被误报为病毒。处理方式：

1. 选择"仍要运行"
2. 或在 Windows 安全中心 → 病毒防护 → 排除项中添加安装目录
3. 长期方案：购买代码签名证书（约 $200/年）

### 数据库 Schema 变更

如果更新改了数据库表结构，需要在 `backend/db/init.py` 的迁移逻辑中处理，确保旧数据库能自动升级。

### .env 配置不会丢失

打包模式下 `.env` 只在首次运行时创建模板，已存在的 `.env` 不会被覆盖。用户更新应用后无需重新配置 AI Key。
