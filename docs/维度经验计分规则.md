## 一、核心变更

### 1.1 三个概念

| 概念 | 说明 | 使用状态 |
|------|------|---------|
| **维度经验（dimension_exp）** | 各维度内部累计的原始经验值，用于维度升级（上限 140 级） | ✅ 生效 |
| **全局经验倍率（global_rate）** | 维度经验计入全局总经验时的折算系数 | ✅ 生效 |

> **已清理的遗留字段（2026-09-17）**：`CATEGORIES` 里原来还定义了一个
> `exp_rate`（health 10 / study 10 / relation 8 / work 12 / create 8 /
> finance 6 / hobby 7 / soul 9）。它从设计之初就**没有任何计分函数读取过** ——
> 实际经验全靠 `_calc_*` 系列硬编码算出。属于「设计了却没落地」的技术债，
> 已连同字段一起删除。
>
> 当时的判断是「要么是历史遗留，要么是后续统一计分公式的预留位」；
> 结论是**不保留预留位** —— 真正要做统一计分公式时，`_calc_*` 必然要重写，
> 那时再引入一个字段比现在守着一个没人读的常量更清楚。

全局总经验计算公式：
```
全局总经验 += round(dimension_exp_earned × global_rate)
```

> 前端展示全局经验时**向下取整**，但后端保存实际数值。

|------|------|------|
| 学习/阅读/课程 | 30 EXP / 小时 | 最小计分块 20 分钟，不足向下取整 |

- 1h05m（65分钟）→ `floor(65/20) × 10 = 3 × 10 = 30 EXP`

### 2.2 健康（global_rate: 1.0）

健康维度包含两种互斥的行为模式：**睡眠** 和 **运动**。

#### 睡眠模式（一天只能一次）

**入口**：点击健康后，进度条下方出现左右两个时间输入框：
- 左：睡觉时间（时:分）
- 右：起床时间（时:分）

**规则**：
- 两个时间都不填 → 按运动模式处理（可多次记录）
- 填写了睡觉和起床时间 → 按睡眠模式处理（一天只能记录一次）
- 睡眠时长 = 起床时间 − 睡觉时间（跨天自动计算）
- 若睡眠时长不在 6~9 小时之间 → 无效，当日失去睡眠经验机会

**基础睡眠经验计算**：假设理想入睡时间为 23:00

| 入睡时间 | 基础经验 | 公式 |
|---------|---------|------|
| 23:00（含）前 | +20 EXP | 全额奖励 |
| 23:00 后 | 逐减 | 每延后4分钟扣1 EXP，直到0为止 |

**公式**：`max(0, 20 - floor(max(0, 入睡分钟数 - 23:00对应分钟数) / 4))`

> ⚠️ 晚睡扣减的是"本该获得的20EXP"中的一部分，不会出现已获得经验减少的情况。系统不会扣除已获得的经验。

**示例**：
- 23:00 睡觉 → 20 EXP
- 23:08 睡觉 → 20 - 8/4 = 18 EXP
- 23:20 睡觉 → 20 - 20/4 = 15 EXP
- 00:20 睡觉 → 20 - 80/4 = 0 EXP

#### 作息规律系统

> ⚠️ **修正**：原文档写"睡 23:00~00:00，起 07:00~08:00"，与代码不符。

**规律定义**（`constants.py:_check_is_routine`，192 行）：

| 项 | 实际判定区间 | 代码 |
|---|---|---|
| 睡觉时间 | **22:00 ~ 24:00** | `sleep_minutes < 22*60 or sleep_minutes > 24*60` → False |
| 起床时间 | **06:30 ~ 08:30** | `wake_minutes < 390 or wake_minutes > 510` → False |

> 0:00~12:00 的入睡时间会 +24h 视为跨天晚睡，所以"凌晨 1 点睡"落在 25:00，超出 24:00 上限 → 不规律。

**连续规律机制**：
- 连续 5 天满足规律定义 → 第 5 天标记为"已连续规律5天"（但当天**不**给额外经验）
- **从第 6 天开始**，每天额外 +15 EXP（在基础睡眠经验之上叠加）
- 当天不符合规律定义 → 失去"作息规律"状态，连续天数归零（有保护时除外）

代码实现（`constants.py:_calc_routine_bonus`）：

```python
if streak < 6:
    return 0
return 15
```

调用时传 `streak + 1`（今天也计入连续天数），所以"第 6 天起"的语义成立。

**保护机制**：
- 当连续规律天数 ≥ 10 天后 → 获得一次保护机会（不可叠加，即最多持有1次）
- 保护效果：某天不符合规律时，消耗保护机会，当天**不加额外经验**（不+15 EXP），但连续天数**不重置**
- 保护消耗后，从下一天起重新计算连续 10 天才能再次获得保护
- 已有保护机会时，连续天数继续增长，但不会额外获得第二次保护

**实现位置**：`routers/actions.py:26 _update_streak_logic()`，状态持久化在 `routine_streak` 表（`user_id / streak / has_protection / last_date`）。

```python
if not is_routine:
    if has_protection:
        return current_streak, False   # 消耗保护：天数保留，经验不加
    return 0, False                    # 无保护：归零

# 今天符合规律：按 last_date 与今天的差值判连续
days_diff == 1  → streak + 1
days_diff  > 1  → 重新计数 1
days_diff == 0  → 同一天，不重复计数

if new_streak >= 10 and not has_protection:
    new_protection = True              # 满 10 天获得保护
```

**举例**：
- 第1~5天：规律作息，连续天数=5，不触发额外经验
- 第6~12天：规律作息，连续天数=12，每天+15EXP，第10天获得保护机会
- 第13~15天：规律作息，连续天数=15，每天+15EXP
- 第16天：不符合规律 → 触发保护，当天不加15EXP，但连续天数保留（=15）
- 第17天起：规律作息，连续天数继续增长（=16+），每天+15EXP
- 需从第17天起再连续10天（到第27天）才能再次获得保护机会

## 三、各维度计分公式一览

| 维度 | 类型 | 计分方式 | 公式 / 规则 | 实现函数 |

## 五、核心设计原则

1. **不扣减已获得经验**：所有规则（包括晚睡扣减）只影响"本次应得经验"，不会减少已获得的经验值
2. **睡眠一天一次**：填了睡觉+起床时间后按睡眠模式处理，当日不可再次记录（`has_sleep_record_today`）
3. **运动可多次**：不填时间即为运动模式，一天可多次记录
4. **保护机制不叠加**：最多持有1次保护机会，消耗后重新计算10天
5. **全局经验**：`dimension_exp × global_rate` 折算后计入总等级，前端展示时向下取整
6. **总经验由维度实时 SUM 反推**：`services/exp_service.py` 每次发经验后从 `user_dimensions` 表 `SUM` 出总经验，再反解等级——维度表是唯一真相源，不维护冗余的总经验字段
